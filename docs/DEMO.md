# 🎬 Сценарий видео-демо (≤ 7 минут, без монтажных склеек)

Структура — по требованиям ТЗ: концепция → архитектура → живое демо → метрики F1@1/@5 →
дополнительная функция после поиска → выводы.

## 0:00–0:50 — Концепция (слайд + закадровый голос)

- Проблема: покупатель у полки, десятки российских вин, международные приложения их не знают.
- Решение: фото этикетки → карточка именно этого вина, без экрана выбора вариантов.
- Ключевая идея: **трёхуровневый гибрид + data flywheel** —
  дешёвый Tier-1 (эмбеддинг + геоверификация) → VLM/OCR-арбитр только при неуверенности →
  логи уходят в активное обучение, которое переносит знания в дешёвый Tier-1.

## 0:50–1:40 — Архитектура (слайд со схемой из `ARCHITECTURE.md`)

- `gateway` — единственная публичная точка; UI знает только его HTTP API.
- Модули независимы, общаются по HTTP/JSON, каждый собирается в свой контейнер.
- Показать `.grace/` (граф модулей, verification, changes) — как проект управляется контрактами.

## 1:40–4:00 — Живое демо (экран, без склеек)

1. Открыть `http://127.0.0.1:3000`, показать мобильную вёрстку (DevTools: iPhone).
2. Снять/выбрать фото этикетки → **карточка вина**: название, винодельня, регион, сорт, цвет,
   сладость, год, описание.
3. Показать определение по API-ответу: `slug`, `path`, `latency_ms`
   (`curl -X POST -F image=@data/samples/eval_queries/019c68d0.jpg http://127.0.0.1:8080/v1/scan`).
4. Отдельно показать контракт организатора: `POST /v1/eval/predict` → `{"slug": "..."}`.
5. Случай «вино не найдено»: загрузить любое фото без этикетки (пейзаж, предмет) →
   интерфейс показывает ближайшие кандидаты, а не пустой экран.

## 4:00–5:00 — Метрики F1@1/@5 и SLA

Показать реальные отчёты и команды:

```bash
make eval | tail -20
make demo-eval      # официальные 2 контрольных фото организатора: latency и кандидаты
```

| Метрика | Значение | Где смотреть |
|---|---|---|
| synthetic proxy acc@1 / acc@5 | 0.685 / 0.790 | `reports/baseline-c003-after.json` |
| группа near-duplicates acc@1 | 0.690 (групповая) | там же, `group_accuracy@1` |
| self-retrieval acc@1 | 0.985 | там же |
| latency демо на официальных фото | `make demo-eval` → `reports/predictions.eval_queries.report.json` |
| синтетический baseline | полевого набора в комплекте нет — качество измеряется proxy-набором | `reports/baseline.json` |

Обязательно проговорить: полевой набор в комплект не входит, используются только официальные
материалы конкурса; F1 измеряется на синтетическом proxy-наборе (`docs/LIMITATIONS.md`).

## 5:00–6:10 — Функция после поиска (retention)

1. **Цифровой сомелье**: выбрать блюдо/бюджет/стиль → рекомендации и строка «Подача: …».
   Показать, что при недоступной локальной LLM фича продолжает работать (подбор по каталогу,
   бейдж «подбор по каталогу»).
2. **Похожие вина из других виноделен**: список с причиной совпадения
   (`curl -s http://127.0.0.1:8080/v1/similar/kokur-suhoe-2025`).
3. **Энотуризм**: блок с регионом и винодельней.

## 6:10–7:00 — Выводы

- Что работает: end-to-end пайплайн, измеримый baseline, retention-фичи, воспроизводимый запуск
  (`make up` / `docker compose up`), GRACE-контроль качества артефактов.
- Что честно ограничивает: домен-разрыв (вырезы ↔ полевые фото), покрытие метаданных каталога
  (год у 5.5% записей), локальные VLM/LLM не читают этикетки в бюджет SLA.
- План роста: кириллическая OCR-модель, дообучение на аугментациях, OCR/VLM как офлайн-учитель.
