# 🎬 Сценарий живого демо (≤ 7 минут)

Структура — строго по требованиям ТЗ: **концепция → архитектура → живое демо → метрики F1@1/@5 →
функция после поиска → выводы**. Все команды и маршруты ниже существуют в репозитории;
числа взяты из `reports/final.json` и `reports/participant_run.json` (не выдуманы).

## Предварительная подготовка (до записи)

```bash
make setup                 # venv + зависимости (requirements.txt) + bun install
make etl                   # каталог: 2103 slug
make index                 # векторный индекс + признаки геоверификации (+ голова, если есть)
# локальные модели на хосте (опционально, для observer/сомелье):
ollama serve &             # :11434 — qwen3.5:9b, gemma4:e4b, qwen3-embedding:0.6b
# сервисы (можно локально, можно docker compose):
PYTHONPATH=. .venv/bin/python -m uvicorn services.normalize.app.main:app --port 8081 &
PYTHONPATH=. .venv/bin/python -m uvicorn services.retrieval.app.main:app --port 8082 &
PYTHONPATH=. .venv/bin/python -m uvicorn services.vlm.app.main:app       --port 8083 &
PYTHONPATH=. .venv/bin/python -m uvicorn services.matcher.app.main:app   --port 8084 &
PYTHONPATH=. .venv/bin/python -m uvicorn services.gateway.app.main:app   --port 8080 &
make warm                  # прогрев retrieval: первый запрос не платит за загрузку модели
make web-dev               # UI на http://127.0.0.1:3000
```

> Вариант «всё в Docker»: `make images && cp .env.example .env && docker compose up --build -d`.
> Перед записью проверить: `curl -s http://127.0.0.1:8080/v1/health`.

## 0:00–0:45 — Концепция (слайд + закадровый голос)

- Проблема: покупатель у полки, десятки российских вин, международные приложения их не знают.
- Решение: **фото этикетки → карточка именно этого вина** (`{"slug": "<вино>"}`) за доли секунды,
  без экрана выбора вариантов.
- Ключевая идея: **дешёвый Tier-1 CV + опциональные слои + data flywheel** — логи уходят в активное
  обучение, которое переносит знания в дешёвый Tier-1.

## 0:45–1:30 — Архитектура (слайд `ARCHITECTURE.md`)

- `gateway` — единственная публичная точка; UI знает только его HTTP API.
- Пайплайн: нормализация → Tier-1 CV (SigLIP 2 + геоверификация ORB) → near-dup/OCR-сигнал → решение.
- Модули общаются по HTTP/JSON и **не импортируют друг друга**; UI удаляем без влияния на ML.
- Показать `.grace/` (граф модулей, verification, changes) — как проект управляется контрактами.

## 1:30–4:00 — Живое демо (экран, без склеек)

1. **Фото из каталога → карточка.** Открыть `http://127.0.0.1:3000` (DevTools: iPhone), отправить
   эталонное фото из `data/samples/eval_queries/`. Показать карточку: название, винодельня, регион,
   сорт, цвет, сладость, крепость, температура подачи, гастрономические сочетания, изображение.
   ```bash
   curl -s -X POST -F image=@data/samples/eval_queries/019c68d0.jpg \
     http://127.0.0.1:8080/v1/scan | jq '{slug, confidence, path, latency_ms, top5}'
   ```
2. **Контракт организатора.** Показать, что зачётный ответ — плоский (`POST /v1/eval/predict`):
   ```bash
   curl -s -X POST -F image=@data/samples/eval_queries/019c68d0.jpg \
     http://127.0.0.1:8080/v1/eval/predict      # → {"slug": "..."}
   ```
3. **Неоднозначное → top-10.** Отправить фото серии-двойника; показать `SCAN_TOP_K=10` — до десяти
   кандидатов вместо единственного ответа (`top10` в UI и `top5[]` + `scan_top_k` в API).
4. **Вне каталога → аналоги.** Загрузить фото вина, которого нет в каталоге (или пейзаж/предмет):
   система отдаёт `not_found` и **аналоги**, а не пустой экран или неверный ответ.
   ```bash
   curl -s "http://127.0.0.1:8080/v1/similar/kokur-suhoe-2025?limit=6"
   ```

отсутствует** — полевое качество измерит организатор (`docs/LIMITATIONS.md`).

## 5:00–6:10 — Функция после поиска (retention)

1. **Цифровой сомелье.** Экран `/sommelier`: выбрать блюдо/бюджет/стиль → рекомендации и строка подачи.
   Показать, что при недоступной LLM фича работает по каталогу (бейдж «подбор по каталогу»).
2. **Вкладка «Обучение»** (`/learning`). Показать цикл обратной связи: голоса → порог доверия
   (≥3 независимых сессии и согласие с консенсусом) → очередь модератора → датасет.
   `curl -s http://127.0.0.1:8080/v1/learning/summary`
3. **Энотуризм.** Блок с регионом и винодельней: `curl -s http://127.0.0.1:8080/v1/enotourism/kokur-suhoe-2025`.
4. **Observer как «quality mode» (по желанию, отдельно от зачётного пути).** Включить
   `OBSERVER_ENABLED=1`, показать свободный текст наблюдения → поиск по всему каталогу.
   Оговорить: **по умолчанию выключен**, для зачёта не используется (лимит 10 с).

## 6:10–7:00 — Выводы

- **Что работает:** end-to-end пайплайн, измеримый proxy-базлайн, совместимость со скриптом
  организатора (100/100), retention-фичи, воспроизводимый запуск (`make gate`, `docker compose`),
  GRACE-контроль качества артефактов.
- **Что честно ограничивает:** домен-разрыв (вырезы ↔ полевые фото), покрытие метаданных каталога,
  отсутствие ground truth, локальные VLM/LLM не читают этикетки в бюджет SLA.
- **План роста:** 10–20 полевых фото → повторная калибровка; доменный/облачный реранкер при появлении ключа.

## Резервные команды (если что-то отвалится в кадре)

```bash
curl -s http://127.0.0.1:8080/v1/health            # gateway
curl -s http://127.0.0.1:8082/health               # retrieval: модель, индекс, голова
curl -s -X POST http://127.0.0.1:8082/warmup       # явный прогрев
docker compose config >/dev/null && echo "compose ok"
grace status --path .                              # состояние GRACE-проекта
```

**Чего в демо не показывать как рабочее:** OOD-числа как достижение, «уверенные» проценты по одному
фото, кириллический OCR и PaddleOCR-VL как онлайн-пути (первый склеивает цифры, второй требует
~3 минут на кадр), observer как часть зачётного скрипта.
